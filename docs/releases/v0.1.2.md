# SeasonLens 0.1.2

Experimental release for repeat XLSX imports with explicit local configuration profiles.

Use the [live app](https://eluyz.github.io/SeasonLens/) in English or Polish, or extract the complete frozen browser ZIP. Start with the [invented-data walkthrough](https://eluyz.github.io/SeasonLens/walkthrough.html) and [profile-reuse instructions](https://github.com/eluyz/SeasonLens/blob/v0.1.2/docs/GETTING_STARTED.md#reuse-an-xlsx-import-profile). No account is needed.

## Changes

- Download a JSON settings profile after successful XLSX validation, then load it against the next workbook to restore worksheet, physical rows, date/value columns, declared titles/units/roles and parsing conventions.
- Exact worksheet and selected column/header compatibility checks. A corrupt or incompatible profile rejects without partially changing the existing configuration. Inspect the preview, validate the new observations and use the separate Add action.
- The current analysis cutoff is preserved. Blank-skipping and cached-formula permissions reset on profile load and need explicit consent when appropriate.
- English/Polish controls and messages, repeat-import documentation and checks for valid, malformed and structurally changed imports.

## Privacy and boundaries

Profiles contain settings and potentially private worksheet/header names and instrument titles. Keep them private. They exclude observations, the original workbook filename, cutoff and blank/formula permissions. They are downloaded only on request; no automatic browser storage, upload, cloud synchronization or database persistence is added. A profile neither recovers imported prices after reload nor certifies new workbook contents. CSV profiles are unsupported.

Six built-in instruments and the example workbook remain invented, with fixed sample cutoff 2026-10-06. There is no new market-data source, automatic collection, telemetry or analytical formula. Existing browser imports remain in tab memory. XLSX imports and profiles do not update the separate private SQLite database.

Publication requires the full suite, Linux Python 3.10/3.12 checks, isolated installed-wheel verification, public-page build and generated-source verification. Recorded execution and deployment results belong in [STATUS.md](https://github.com/eluyz/SeasonLens/blob/v0.1.2/STATUS.md); these requirements do not imply that every platform was tested. Physical phones, Safari, native PDF dialogs and Windows/macOS execution remain unverified.
