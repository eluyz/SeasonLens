# Agent workflow

The user authorizes a coordinating agent to delegate implementation and review in this project. Delegate bounded independent tasks; keep a single writer per file. Do not create additional agent hierarchies without a concrete need.

Read SPEC.md and STATUS.md before changing behavior. Use BACKLOG.md for scope and DECISIONS.md for rationale. Preserve invalid-input errors, missing-data visibility and equal-year weighting requirements for future profiles.

Each task must have a scope, acceptance criteria and explicit file ownership. Review significant mathematical changes independently; passing tests does not replace checking the definition. Use hand-calculated examples, not tests that merely duplicate implementation.

Use synthetic data for public examples. Do not add company, client or licensed market data without authorization and established redistribution rights. Do not claim public adoption, publication, completed milestones, program acceptance or continuous background execution unless verified.

Run the relevant tests once changes are ready. Record actual commands and limitations in STATUS.md. Public account access, paid infrastructure and application submission require the owner's applicable authorization; routine local implementation proceeds autonomously.
